# 账户、会员与权限

观星采用持久化账号密码登录，参考天枢的首次初始化与后续登录流程。升级后旧访问令牌不再用于登录，原有应用和监控数据保留。

## 首次启动与日常使用

1. 启动 API、前端和原有 MySQL。数据库初始化会幂等创建账户相关表。
2. 首次打开前端创建唯一超级管理员。数据库行锁保证并发请求只能创建一位超管；完成后初始化入口关闭。请在将新实例开放给外部用户之前完成此步骤。
3. 保存首次注册显示的恢复码，之后使用账号和密码登录。恢复码不在数据库中明文保存，页面关闭后无法再次查看。
4. 外部用户从登录页注册，固定为普通用户。超管可在“账户管理 → 角色权限”关闭或重新开启注册。
5. 右上角账户下拉菜单提供“用户设置、主题设置、退出登录”。“用户设置”进入账户管理页的本人记录，在编辑弹窗中使用当前密码修改账密；修改后所有旧会话失效，需要重新登录。侧栏不再提供单独的“我的账户”。
6. 忘记账号或密码时，在登录页使用恢复码设置新密码，系统显示原账号和新的恢复码。旧恢复码立即作废。普通用户也可联系超管重置账号密码；超管重置密码时生成新的恢复码供安全交付。超管可以在同一个编辑弹窗修改自己的账密；不允许停用或降级唯一超管。

账号不区分大小写，允许 3–64 位字母、数字、下划线、点和短横线。密码长度 10–128 个字符。此版本使用恢复码，不发送邮件或短信；恢复码遗失后，可在“账户管理 → 编辑自己的账户 → 安全设置”验证当前密码、重新生成并下载恢复码。账号、密码和恢复码全部遗失时，使用下面的服务器端应急重置。

## 权限配置

权限按 18 个业务模块和账户管理模块区分“查看”和“操作”，操作权限自动包含对应查看权限。前端按权限显示菜单、拦截页面，API 独立校验权限，包括直接访问 URL、修改请求和导出下载。通用商店目录、分类计数和图标供登录后的页面显示使用。

| 类型 | 默认权限 | 配置方式 |
| --- | --- | --- |
| 超级管理员 | 全部业务功能及账户权限管理 | 唯一初始化账户；不支持从外部注册或修改角色提升 |
| 普通用户 | 概览、应用库、榜单中心、全球排行榜、市场分布的查看 | 外部注册和旧普通账户默认继承此组 |
| 会员 | 除采集中心和账户管理外所有业务模块的查看 | 支持设置到期时间，留空表示长期 |
| 自定义用户组 | 由超管逐项勾选 | 在“账户管理 → 角色权限”选择“新增用户组”，填写组名、勾选权限并保存。选中已有组可以修改名称和权限 |

超管在“账户管理 → 新增账户”设置账号和密码，并勾选一个或多个用户组。编辑已有账户也可调整分组。开启“继承所选用户组的合并权限”时，只合并勾选组的权限。会员到期后，会员组按普通用户组计算，其余所选组继续生效。单独配置的个人权限优先于组权限，适用于已有个人授权的账户。

组权限修改对已有会话的下一次请求生效。单用户变更、停用及密码重置会撤销该用户现有会话。账号列表支持搜索，每页 100 条。操作日志按结束时间展示最近 200 条安全操作。同一操作人连续对同一目标执行相同动作时，保留首次记录的开始时间，结束时间更新为最近一次操作时间。其他用户的操作独立记录。升级前的记录使用原时间显示起止时间。

通用采集管理和任务配置需要采集中心操作权限，关键词、重点监控等模块自己的任务控制需要对应模块的操作权限；应用详情一键采集和全球榜单采集计划还要求来源模块操作权限。榜单与推荐历史按目标真实类型授权，不能通过更改目标 ID 越权。应用详情包含该应用的排名、关键词和事件摘要，概览包含全站统计；本版本按页面功能授权，不按国家、商店、应用或创建人隔离数据。导出权限允许查看共享导出记录及下载导出数据，授予前请确认用户适合访问这些共享资源。

会员开通、延期、降级当前由超管手工管理，未接入支付、订单或自动续费。后续支付服务应在验证支付回调后由后端更新会员身份与到期时间，不能信任浏览器传入的会员状态。

## 委派账户管理

超管能查看所有用户，并通过编辑弹窗配置基本信息、会员状态及逐页面访问/操作权限。“账户管理、角色权限、操作日志”和弹窗内“基本信息、页面权限、安全设置”均采用下划线式标签切换，支持方向键。

普通用户和会员默认只能从右上角编辑自己的账密。授予 `administration:read` 后可以查看非超管账户；再授予 `administration:write` 后可以编辑这些账户。委派管理员不能查看或编辑超管、不能修改自己的角色和权限、不能分配自己没有的权限或管理权限高于自己的账户；账户管理权限的新增授权、默认角色权限和注册开关仅超管能修改。通过修改密码接管更高权限账户、角色继承及会员到期进行间接提权，也会被后端拒绝。

## 超管全部凭据遗失时

有服务器访问权限和项目数据库连接权限的运维人员，在项目目录执行：

```powershell
docker compose -f compose.yaml --env-file .env --profile console exec web appmon accounts recover-admin
```

本地 Python 部署则执行：

```powershell
.\.venv\Scripts\python.exe -m appmon accounts recover-admin
```

该命令会显示现有超管账号，要求输入 `RESET`，随后交互式输入新账号（可留空）及两次新密码。密码输入不回显，也不通过命令参数、环境变量或文件传入。完成后生成新的恢复码供立即保存，同时撤销旧恢复码和所有超管会话并记录安全审计。没有旧账号、密码或恢复码也可以操作，但必须先取得服务器和数据库访问权限。该功能没有 HTTP 接口，不在登录页提供免凭据重置。

## 部署与会话

- `APPMON_ALLOWED_HOSTS` 填实际前端域名（不含端口），保留所需的本地地址。
- HTTPS 部署（含反向代理终止 TLS）设置 `APPMON_COOKIE_SECURE=true`；本地 HTTP 开发使用 `false`。
- Cookie 为 HttpOnly、SameSite=Strict，8 小时到期；数据库只保存随机会话令牌的摘要，重启 API 不会主动清空有效会话。退出、停用、修改凭据均会撤销会话。
- 修改类请求校验会话绑定的 `X-CSRF-Token`，同时保留 Host、Origin、跨站来源和请求体大小检查。
- 密码使用随机盐 PBKDF2-HMAC-SHA256（600,000 次）保存；登录、注册、恢复及账密修改使用数据库限流，多个 API 实例共享计数。不要在不可信的反向代理头中传入客户端地址来绕过限流；当前同一代理后用户共享 IP 限额。
- API 客户端通过 `/api/auth/login` 登录，保存响应 Cookie，并把返回的 `csrf_token` 用于修改请求。`/api/auth/me` 可恢复当前会话和 CSRF 值。API 定义仅超管可访问。

测试覆盖真实 MySQL 的初始化竞争、注册角色不可提权、旧令牌不可绕过、CSRF、直接 API 越权、会员到期、角色与个人权限、停用、恢复码轮换、凭据修改、会话过期以及共享限流。前端测试覆盖初始化、恢复码保存确认、登录、菜单过滤、个人修改和会员权限编辑。
