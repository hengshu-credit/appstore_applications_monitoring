# 生产构建主题覆盖修复验收

日期：2026-11-10。

## 原因与修复

- 主页面和 API 文档共用 `theme.css`。多入口生产构建将公共主题 CSS 提取到主页面 CSS 之前，基础样式中的固定颜色随后覆盖主题规则。
- 浏览器复现：主题主色为 `#873FF2`，概览四张统计卡片的实际顶边却为 `rgb(127, 187, 192)`（`#7fbbc0`）。构建产物中 `.metric` 的固定 `border-top` 覆盖了公共主题里的 `border-top-color`。
- 基础样式改为直接引用主题变量，统一卡片、导航、链接、表头、提示消息、时间轴边框及弹窗遮罩；市场占比条也改用主题图表颜色派生色。
- 窄屏复核发现概览单列网格被表格最小内容宽度撑开，改用 `minmax(0, 1fr)`，让宽表仅在表格容器内滚动。

## 自动化验证

- 新增生产 CSS 回归测试，真实执行多入口构建，按输出 HTML 的样式链接顺序加载 CSS，再检查组件计算样式。
- 测试在修复前以 `metric accent` 断言失败，实际为 `#7fbbc0`；修复后通过。覆盖 12 个预设、自定义浅色纯色、自定义渐变，以及深浅显示与导航配色的 56 种组合。
- 前端 128 项测试、语法检查和生产构建通过；最后一处网格修正后，生产 CSS 回归测试与 Docker 生产构建再次通过。
- Compose 配置检查、前端镜像构建及运行容器 Nginx 配置检查通过。本地 5173 前端已更新。
- 构建仍有现有 Swagger 文档包超过 500 kB 的体积提示，没有关闭或提高警告阈值。

## 实际浏览器验证

- Chrome 生产页面：当前紫色主题下，四张概览卡片顶边均为 `rgb(135, 63, 242)`，与主色一致。
- 深色桃粉渐变：概览与分组卡片背景为 `rgb(21, 29, 49)`，文字为 `rgb(237, 242, 255)`；导航跟随配色，业务弹窗背景一致，遮罩为 `rgba(2, 6, 23, 0.72)`。
- 390px 视口：页面可用宽度与滚动宽度均为 380px（另有 10px 滚动条），四张卡片分两列展示。宽表在 298px 容器内滚动，内容宽度 553px，不再撑宽整页。
- 验证结束后恢复原来的浅色凝液紫主题、深色导航和默认浏览器视口。
