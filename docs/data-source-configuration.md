# 数据源配置与首轮采集容量

管理菜单的“数据源配置”（`#datasources`）统一列出商店、RSS、图片 CDN、AppGoblin 批量包、已授权市场数据与 Apple Ads 等 12 类来源。

## 配置迁入与回显

- 首次读取时，将 `data/secrets/source-profiles.json` 中已配置的接入地址、允许域名迁入 `data_source_configs`，已在后台保存的值优先，重复打开页面不会覆盖。
- 账户邮箱回显；密码、Token、会话 Cookie 不返回前端。凭据继续使用现有 Fernet 密钥加密，不更换已有账户密钥。
- 接入地址修改后，原凭据保留但被标记为 `endpoint_changed`；重新保存凭据前不向新地址发送旧凭据。
- Apple Ads 支持后台保存广告账户 ID 和 Token；已有环境变量凭据可幂等迁入，Token 留空保留，前端仅显示配置状态。
- 配置 API 位于 `/api/data-sources/config/{name}`，沿用不可委派的管理员权限。

## 经过实测的详情批量

2026-11-07，在同一美国/英语市场，使用已有成功应用 ID 进行了 4 次公开接口验证：Apple 100/200 个均完整返回，Google 50/100 个均通过身份和详情解析校验。结果计数见运行环境 `data/exports/batch-capacity-probe.json`。

后台可将 Apple 详情批量设为最多 200，Google 详情设为最多 100。国家、语言、会话仍隔离；其他 Google 任务维持服务配置中的原批量。HTTP 413/414 触发拆分重试，429/403 不通过拆分绕过控频。已返回结果保持按目标映射，缺项继续单独补验。

这些数字是当前实测能力，不能视作来源永久承诺。商店请求间隔、每日预算、磁盘保护和 Retry-After 继续生效。该优化不修改任务采集深度与刷新周期。

新环境在安装项目后可运行 `python scripts/configure_initial_collection.py --apply`（或参考部署文档通过标准输入在 web 容器内执行脚本），应用已验证的 200/100 详情批量，并把共享间隔降至最多 1 秒，让不同商店使用各自的既有请求窗口。该命令保持各商店间隔、每日配额和暂停状态，输出容量下界与未满足条件，不把参数调整视为达标证明。

## 免费批量字段基线

来源与许可：

- [AppGoblin 公开仓库](https://github.com/appgoblin-dev/appgoblin-data)，CC BY 4.0。
- [AppGoblin 免费数据目录](https://appgoblin.info/free-app-datasets)，更完整指标与英文描述包要求免费账户登录。目录明确包含历史快照，不能等同于全应用、所有市场、全部实时字段。

后台“公开批量数据包”读取 `data/raw` 中已下载的目录、存活应用、指标、描述文件，支持导入、暂停与续传；不猜测或绕过需登录的下载链接。Hosted 文件可识别 `appgoblin_store-apps-metrics_*.tsv.xz` 和 `appgoblin_descriptions_*.tsv.xz`。

导入逐行保留源字段、应用身份、来源日期和文件 SHA256。每 2,000 行提交检查点；异常或磁盘保护暂停后从已提交位置续传。新环境的 `public_app_baselines` 使用 InnoDB 透明压缩。数据不写成官方商店 `listings` 成功，不改既有任务状态、失败记录或暂停设置。来源拒绝行会单独计数，并显示“有拒绝行”，不会冒充完整成功。

API：

- `GET/POST /api/data-sources/baseline-imports`：进度、文件清单及入队。
- `GET /api/data-sources/baselines/{store}/{app_id}`：保留来源和日期的完整基线字段。
- `GET /api/data-sources/initial-capacity`：24 小时目标的容量下界与缺口。

## 24 小时目标的判定

页面的理论下界只计算“全库每个应用一个市场的一次详情”，按全部满批、一次成功估算。全球市场展开、评论、关键词、素材、补验和授权来源缺失会增加实际工作量，因此不能把该数字当作全内容预计完成时间。

部分历史字段导入不计为完整应用采集完成；当前没有经过验证的免费来源覆盖全部全球内容。系统明确显示未满足的条件，不以降低字段、减少国家、删除失败任务、改写历史时间或放宽完成标准实现 24 小时绿灯。

容量报告还提供可用磁盘、保护线及按每商店最多 200 条成功详情样本计算的单份载荷估算。该抽样未包括索引、历史副本、图片，也不代表整个应用总体，不能作为完整采购容量或完成时限承诺。

## 重点采集优先

当前配置的磁盘保护线为 10 GiB。`collection_priority_mode="focus"` 将九成调度机会优先给详情监控、榜单、关键词、评论、权限、素材等非全池队列；每十次保留一次全池机会，重点队列空闲时全池可直接使用空余能力。已暂停的任务仍保持暂停。

请求窗口使用跨进程的有期限排队票据，按最早且当前来源允许的请求分配，避免分页请求连续抢占窗口；来源冷却不会让另一个本已可用的来源被队首阻塞。失联票据自动过期。

写入批次先按应用身份顺序锁定已有应用行；遇到 MySQL 1205/1213 时回滚并重试数据库事务，沿用已获取结果，不重发 HTTP、不重复累计处理数。其他数据库错误仍报告失败。
