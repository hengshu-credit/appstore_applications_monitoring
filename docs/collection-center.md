# 统一采集中心

页面入口：`http://127.0.0.1:5173/#collection`。本页管理现有全部采集类型，业务结果页面的配置入口统一跳转到这里。

## 顶部市场选择

- 应用商店：点击展开 Google Play / App Store 列表，选项和选中值均显示本地 SVG logo 与名称。
- 国家 / 地区：保留可搜索、按地理区域分组的选择器。
- 请求语言：点击展开语言列表，可搜索中文名称或代码；支持输入合法的自定义语言标签，例如 `en-ph`。选择语言不会自动更改国家。
- 三个选择器及刷新、主题按钮使用相同的 42px 高度；支持键盘选择和 Escape 关闭。侧栏使用统一 24px 视框、1.7px 线宽的 SVG 图标。

## 采集任务

集中管理应用详情、关键词排名、分类榜单、用户评论和 Apple Today 编辑推荐。列表跟随顶部商店，可选择全部商店；可继续按任务类型、国家、状态和目标文本筛选。每页 50 条，服务器分页，可继续查看全部任务，不再只显示前 1000 条。

分类矩形卡片分别汇总重点应用详情、关键词排名、分类榜单、评论、推荐和图标的总量与五种状态。状态文字只在顶部统一图例出现一次；卡片使用占比条、状态符号及数量，悬停可查看完整状态名，键盘和屏幕阅读器也可识别状态并筛选。点击类型或状态直接筛选列表，重置分页；分类卡片遵循商店、国家、语言和搜索条件，保留全部类型与状态作为上下文。全池详情另有独立卡片，统计所有商店与市场，排除重点监控组合，并单独标出当前流程未启用的市场；点击进入基础流程管理。

- **新建采集计划**：顶部市场决定新目标的商店、国家和请求语言；勾选所需类型，填写应用 ID / 关键词、周期和结果上限。榜单支持免费、付费、畅销类型及当前商店分类。先预览，再确认提交。
- **编辑**：调整周期、结果上限或重点应用分组，保留启用状态及历史。应用、关键词、市场属于目标身份，需要变化时新建独立目标。
- **暂停 / 恢复**：支持单个、当前页、跨页筛选结果和所有商店全部任务的批量操作。暂停会使已领取的目标租约失效，过期结果不覆盖有效历史。
- **批量修改周期**：支持已选、跨页筛选或全部配置任务，保留历史与暂停状态，取消原租约并从保存时间按新周期重新排期。可将低优先级任务改为每周采集以降低每日负载。
- **重试筛选内失败任务**：仅重新安排启用、失败且未被领取的匹配任务；保留失败记录与退避信息，仍受共享冷却和预算约束。
- **立即采集**：将启用目标安排为到期任务；由后台按租约和限速处理，正在执行的请求不重复领取。暂停目标须先恢复。
- **日志**：每个目标都有独立日志入口。窗口默认每 2 秒按游标增量更新，显示执行编号、开始、限速等待、HTTP 请求/响应、完成条数、失败原因和耗时；运行中也可以查看。支持暂停更新、跟随最新、回到最新和查看更早记录。
- **计划记录**：查看最近 100 个配置计划及进度；失败计划可从断点重试。“已配置”表示目标已经建好，采集完成时间以任务观察记录为准。

应用库批量选择、应用详情和竞品集合的监控入口会携带目标跳转至采集中心。重点监控、关键词、榜单、推荐与评论页面保留结果查看，不再分散配置任务。

## 基础采集流程

此标签页配置三个常驻 `monitor` 流程，设置保存到 MySQL `collection_controls`，由各 worker 读取，不需要手工修改容器里的文件：

| 流程 | 可配置项 |
|---|---|
| 全池应用详情 | 启用、刷新周期、国家列表、请求语言 |
| AppGoblin 公开种子同步 | 启用、检查周期；源固定为 GitHub 公开历史包 |
| 应用发现 | 启用、周期、国家、请求语言、发现关键词、Google 官方分类 ID |

设置在当前请求 / 批次完成后应用；全池周期用于后续成功任务的再次调度，已有排队时间不会整体重排。新增地区会由后台建立对应队列。百万应用仍需按来源限速持续处理，配置周期不是全池刷新时限承诺。种子同步仅检查配置的开源数据仓库。

全池 worker 排除已列入重点监控的应用市场组合，由重点 worker 独立负责，防止全池处理绕过重点任务的暂停状态。一次性 CLI 命令仍可用于显式手工操作，基础流程开关作用于常驻 daemon。

基础流程卡片提供“查看运行日志”，计划执行记录也有日志入口。日志存入 MySQL `collection_logs`，重启容器后保留。功能启用前的执行没有阶段日志，不回填或伪造；窗口会提示暂无日志。默认保留日志，长期运行应按业务需要归档。

实时窗口最多保留最近 2000 行，历史以每页 200 行读取；进入历史模式会暂停自动刷新，点击“回到最新”恢复。窗口关闭后停止轮询，连接失败显示状态并自动重试。日志接口沿用 API 鉴权，只返回对应任务的结构化记录，不读取容器终端或本地任意文件；不记录请求参数、请求体、认证头、Cookie 或代理凭据。

## 接口与验证

- `GET /api/research/collection/tasks`：分页、筛选、状态统计。
- `PUT /api/research/collection/tasks/{resource}/{id}`：编辑目标设置。
- `POST /api/research/collection/tasks/batch`：默认 `scope=selected` 最多 100 个目标；`scope=filtered` 携带筛选条件，`scope=all` 操作全部任务；跨页支持暂停/恢复、周期调整与重试失败。任一目标无效则整批回滚。
- `GET /api/research/collection/activity`：计划记录与 worker 心跳。
- `GET /api/research/collection/logs/{resource}/{identifier}`：任务日志，支持 `after_id` 增量游标或 `before_id` 历史分页，二者互斥。`resource` 为 `watchlist`、`keywords`、`targets`、`plans` 或 `pipelines`。
- `GET/PUT /api/research/collection/pipelines[/{name}]`：读取或保存基础流程设置。
- 原有计划预览、创建和失败重试接口继续使用。

本地验证覆盖真实 MySQL 的跨类型分页、泰语搜索、原子批量操作、暂停与租约、历史保留、计划深度和配置跨连接读取；前端交互覆盖语言与商店切换、候选词计划、提交前预览以及异步操作期间切换页面。浏览器验收另检查实际容器中的编辑/恢复、深浅主题和 390px 窄屏。

日志用例验证 worker 尚在阻塞请求中时，另一数据库连接已能读取开始日志；同时覆盖游标隔离、重复增量去重、失败与重试执行编号、凭据脱敏、历史翻页和关闭后停止更新。

## 整体控频与离线迁移

`GET/PUT /api/research/collection/limits` 通过采集权限读取/保存全局间隔、商店间隔、冷却、每日请求预算与暂停开关；所有商店 worker 共享数据库额度。默认整体间隔 5 秒，受限后至少冷却 900 秒，每日请求预算默认 0（不限），不以默认总量限制截断每日采集；用户主动保存的预算仍保留。预算计入已放行的请求尝试，包括失败请求；一次多应用 lookup 或 Google 多 RPC 请求只计一次。预算重置时间为 UTC 00:00（北京时间 08:00），不是滚动 24 小时。等待中的请求会重新检查冷却窗口，不提前预订大量请求槽位。控频表单默认折叠，展开即可配置。

预算耗尽、请求暂停或长冷却期间，详情、关键词、榜单/评论/推荐和图标 worker 不继续领取队列，避免把整个积压队列逐个转成失败重试。种子包下载、手动第三方数据源操作不计入该商店请求预算。

## 批次执行与大量任务管理

- 全池和重点应用详情使用相同批次执行逻辑。App Store 按商店、国家、语言聚合，每次 lookup 最多 50 个 ID；`config.toml` 的 `apple_lookup_batch_size` 可设为 1–50，设为 1 恢复单应用请求。依据 [Apple Lookup 接口说明](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/LookupExamples.html)使用多 ID 查询，并以真实应用进行双 ID 请求验证。
- 领取阶段只锁定下一次请求所需的任务，短事务协调并发领取；HTTP 在事务外执行。每个应用保持自己的周期、结果、历史和租约有效性检查；不把整个批次合并成一条业务观察。
- 批量响应按 ID 映射，不依赖返回顺序。缺失条目先安排单独 lookup 核验；结构异常或 HTTP 限流保留原数据，不把异常批次判成应用批量下架，也不立即拆成大量单请求重试。
- Google 详情、关键词、榜单和评论使用公开网页本身的 RPC，将同国家、语言及采集类型的最多 20 个目标装入一次 HTTP 请求；`google_rpc_batch_size` 可设为 1–20，1 恢复逐目标采集。详情使用完整字段投影，关键词保留原查询条件与返回顺序，榜单保留每个目标的深度。来源、解析器版本和观察覆盖语义均保持一致。
- Google 评论按轮次合并分页请求，每个应用独立维护游标、去重集合、目标深度和页数边界，直到达到原本的结束条件；不因为同批其他应用完成就提前停止。Apple 关键词、评论与编辑推荐保留原有协议。
- Google 响应通过每次调用的独立标识映射，支持乱序返回；详情另外校验应用 ID。单项缺失或格式异常只将该目标标成失败，按原退避机制改用原有单目标协议重试，不保存不完整结果或捏造空数据。HTTP 限流依旧执行共享冷却，不立即拆批轰炸请求。
- 此优化不自动降低目标深度、延长采集周期、删除任务或复用过期数据。请求次数下降来自传输层的合并；原有字段、排名、评论、各目标历史仍独立完整保存。
- 跨页暂停/恢复、周期调整、失败重试使用 MySQL 临时表固定目标集合，并以集合更新及批量日志写入完成同一事务；不将几十万个 ID 拉到 API 内存，不逐任务发出数据库更新。选中任务仍支持至多 100 项的原子操作。
- API 批量操作新增 `action=interval`（携带 `refresh_hours`）及跨页 `action=retry`；跨页立即采集 `refresh` 仍不支持，避免误触全量重采。全池任务通过基础流程控制，不包含在配置目标列表的“全部”操作中。

回归覆盖 105 个同市场 Apple 应用分 3 个 HTTP 请求、21 个 Google 详情/关键词分 2 次请求、完整字段/排名对比、评论独立游标与完整深度、响应乱序/部分缺失、失败目标单独重试、并发领取、暂停后的过期结果丢弃、每日预算跨日重置、图例筛选与跨页周期调整。

2026-11-06 使用真实 Google 接口的小样本验证结果（未写入生产观察数据）：

| 数据 | 原协议所需 HTTP 请求 | 批量请求 | 返回数据 |
|---|---:|---:|---|
| 两个应用详情 | 2 | 1 | 两份详情；已核对原 21 个业务字段 |
| 两个关键词 | 2 | 1 | 各 20 条，沿用原首屏覆盖语义 |
| 两个分类榜单 | 2 | 1 | 各 100 条 |
| 两个应用评论 | 4 | 2 | 各 100 条，独立两页 |

Google 多 RPC 是网页公开协议而非稳定官方 API；批次格式变化时按上述单目标重试保留数据覆盖。请求合并比例取决于同市场待采集应用数量，不代表所有类型都能减少相同比例，也不承诺任意规模在一天内全部采集完成。

完整语义及备份、恢复、打包命令见 [离线部署说明](offline-deployment.md)。
