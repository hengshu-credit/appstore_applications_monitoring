# 统一采集中心

页面入口：`http://127.0.0.1:5173/#collection`。本页管理现有全部采集类型，业务结果页面的配置入口统一跳转到这里。

## 顶部市场选择

- 应用商店：点击展开 Google Play / App Store 列表，选项和选中值均显示本地 SVG logo 与名称。
- 国家 / 地区：保留可搜索、按地理区域分组的选择器。
- 请求语言：点击展开语言列表，可搜索中文名称或代码；支持输入合法的自定义语言标签，例如 `en-ph`。选择语言不会自动更改国家。
- 三个选择器及刷新、主题按钮使用相同的 42px 高度；支持键盘选择和 Escape 关闭。侧栏使用统一 24px 视框、1.7px 线宽的 SVG 图标。

## 采集任务

集中管理应用详情、关键词排名、分类榜单、用户评论和 Apple Today 编辑推荐。列表跟随顶部商店，可选择全部商店；可继续按任务类型、国家、状态和目标文本筛选。每页 50 条，服务器分页，可继续查看全部任务，不再只显示前 1000 条。

分类矩形卡片分别汇总重点应用详情、关键词排名、分类榜单、评论、推荐和图标的总量与五种状态。状态文字只在顶部统一图例出现一次；卡片使用占比条、状态符号及数量，悬停可查看完整状态名，键盘和屏幕阅读器也可识别状态并筛选。点击类型或状态直接筛选列表，重置分页；分类卡片遵循商店、国家、语言和搜索条件，保留全部类型与状态作为上下文。全池详情另有独立卡片，统计所有商店与市场，排除重点监控组合，并单独标出当前流程未启用的市场；点击进入基础流程管理。

- **新建采集计划**：顶部市场决定新目标的商店、国家和请求语言；勾选所需类型，填写应用 ID / 关键词、周期和结果上限。榜单支持免费、付费、畅销类型及当前商店分类。先预览，再确认提交。
- **编辑**：调整周期、结果上限或重点应用分组，保留启用状态及历史。应用、关键词、市场属于目标身份，需要变化时新建独立目标。
- **暂停 / 恢复**：支持单个、当前页、跨页筛选结果和所有商店全部任务的批量操作。暂停会使已领取的目标租约失效，过期结果不覆盖有效历史。
- **批量修改周期**：支持已选、跨页筛选或全部配置任务，保留历史与暂停状态，取消原租约并从保存时间按新周期重新排期。可将低优先级任务改为每周采集以降低每日负载。
- **重试筛选内失败任务**：仅重新安排启用、失败且未被领取的匹配任务；保留失败记录与退避信息，仍受共享冷却和预算约束。
- **立即采集**：将启用目标安排为到期任务；由后台按租约和限速处理，正在执行的请求不重复领取。暂停目标须先恢复。
- **日志**：每个目标都有独立日志入口。窗口默认每 2 秒按游标增量更新，显示执行编号、开始、限速等待、HTTP 请求/响应、完成条数、失败原因和耗时；运行中也可以查看。支持暂停更新、跟随最新、回到最新和查看更早记录。
- **计划记录**：查看最近 100 个配置计划及进度；失败计划可从断点重试。“已配置”表示目标已经建好，采集完成时间以任务观察记录为准。

应用库批量选择、应用详情和竞品集合的监控入口会携带目标跳转至采集中心。重点监控、关键词、榜单、推荐与评论页面保留结果查看，不再分散配置任务。

## 基础采集流程

此标签页配置三个常驻 `monitor` 流程，设置保存到 MySQL `collection_controls`，由各 worker 读取，不需要手工修改容器里的文件：

| 流程 | 可配置项 |
|---|---|
| 全池应用详情 | 启用、刷新周期、国家列表、请求语言 |
| AppGoblin 公开种子同步 | 启用、检查周期；源固定为 GitHub 公开历史包 |
| 应用发现 | 启用、周期、国家、请求语言、发现关键词、Google 官方分类 ID |

设置在当前请求 / 批次完成后应用；全池周期用于后续成功任务的再次调度，已有排队时间不会整体重排。新增地区会由后台建立对应队列。百万应用仍需按来源限速持续处理，配置周期不是全池刷新时限承诺。种子同步仅检查配置的开源数据仓库。

全池 worker 排除已列入重点监控的应用市场组合，由重点 worker 独立负责，防止全池处理绕过重点任务的暂停状态。一次性 CLI 命令仍可用于显式手工操作，基础流程开关作用于常驻 daemon。

基础流程卡片提供“查看运行日志”，计划执行记录也有日志入口。日志存入 MySQL `collection_logs`，重启容器后保留。功能启用前的执行没有阶段日志，不回填或伪造；窗口会提示暂无日志。默认保留日志，长期运行应按业务需要归档。

实时窗口最多保留最近 2000 行，历史以每页 200 行读取；进入历史模式会暂停自动刷新，点击“回到最新”恢复。窗口关闭后停止轮询，连接失败显示状态并自动重试。日志接口沿用 API 鉴权，只返回对应任务的结构化记录，不读取容器终端或本地任意文件；不记录请求参数、请求体、认证头、Cookie 或代理凭据。

## 接口与验证

- `GET /api/research/collection/tasks`：分页、筛选、状态统计。
- `PUT /api/research/collection/tasks/{resource}/{id}`：编辑目标设置。
- `POST /api/research/collection/tasks/batch`：默认 `scope=selected` 最多 100 个目标；`scope=filtered` 携带筛选条件，`scope=all` 操作全部任务；跨页支持暂停/恢复、周期调整与重试失败。任一目标无效则整批回滚。
- `GET /api/research/collection/activity`：计划记录与 worker 心跳。
- `GET /api/research/collection/logs/{resource}/{identifier}`：任务日志，支持 `after_id` 增量游标或 `before_id` 历史分页，二者互斥。`resource` 为 `watchlist`、`keywords`、`targets`、`plans` 或 `pipelines`。
- `GET/PUT /api/research/collection/pipelines[/{name}]`：读取或保存基础流程设置。
- 原有计划预览、创建和失败重试接口继续使用。

本地验证覆盖真实 MySQL 的跨类型分页、泰语搜索、原子批量操作、暂停与租约、历史保留、计划深度和配置跨连接读取；前端交互覆盖语言与商店切换、候选词计划、提交前预览以及异步操作期间切换页面。浏览器验收另检查实际容器中的编辑/恢复、深浅主题和 390px 窄屏。

日志用例验证 worker 尚在阻塞请求中时，另一数据库连接已能读取开始日志；同时覆盖游标隔离、重复增量去重、失败与重试执行编号、凭据脱敏、历史翻页和关闭后停止更新。

## 整体控频与离线迁移

`GET/PUT /api/research/collection/limits` 通过采集权限读取/保存全局间隔、商店间隔、冷却、每日请求预算与暂停开关；所有商店 worker 共享数据库额度。默认整体间隔 5 秒，受限后至少冷却 900 秒，每日请求预算默认 0（不限），不以默认总量限制截断每日采集；用户主动保存的预算仍保留。预算计入已放行的请求尝试，包括失败请求；一次多应用 lookup 或 Google 多 RPC 请求只计一次。预算重置时间为 UTC 00:00（北京时间 08:00），不是滚动 24 小时。等待中的请求会重新检查冷却窗口，不提前预订大量请求槽位。控频表单默认折叠，展开即可配置。

预算耗尽、请求暂停或长冷却期间，详情、关键词、榜单/评论/推荐和图标 worker 不继续领取队列，避免把整个积压队列逐个转成失败重试。种子包下载、手动第三方数据源操作不计入该商店请求预算。

## 批次执行与大量任务管理

- 全池和重点应用详情使用相同批次执行逻辑。App Store 按商店、国家、语言聚合，每次 lookup 最多 50 个 ID；`config.toml` 的 `apple_lookup_batch_size` 可设为 1–50，设为 1 恢复单应用请求。依据 [Apple Lookup 接口说明](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/LookupExamples.html)使用多 ID 查询，并以真实应用进行双 ID 请求验证。
- 领取阶段只锁定下一次请求所需的任务，短事务协调并发领取；HTTP 在事务外执行。每个应用保持自己的周期、结果、历史和租约有效性检查；不把整个批次合并成一条业务观察。
- 批量响应按 ID 映射，不依赖返回顺序。缺失条目先安排单独 lookup 核验；结构异常或 HTTP 限流保留原数据，不把异常批次判成应用批量下架，也不立即拆成大量单请求重试。
- Google 详情、关键词、榜单、评论和权限使用公开网页本身的 RPC，将同国家、语言和请求身份的最多 20 个不同调用装入一次 HTTP 请求，可混合兼容的采集类型；`google_rpc_batch_size` 可设为 1–20，1 恢复逐目标采集。详情使用完整字段投影，关键词保留原查询条件与返回顺序，榜单保留每个目标的深度。来源标识保留；进入续采的关键词结果使用 `serp-v2 / paginated_search`，与旧的首屏观察区分。
- Google 评论优先一次申请目标数量（当前任务深度最高 500），不再固定切成每页 50 条；实测单次返回了 500 条不重复评论。若接口返回短页或跨页重复，则继续使用它的真实游标，每次只申请剩余所需数量，按评论 ID 去重，达到目标或来源明确结束才停止。多个应用的续采仍合并为批次。
- Google 关键词的初始请求参数不是通用的 `limit` 数值，盲目将其中的 20/50 改成 200 会被真实接口拒绝。保留有效的初始协议；当响应提供下一页游标时，通过 `qnKhOb` 自动续采、保持首次出现顺序、按应用 ID 去重，直至达到目标或来源末尾。若来源没有提供下一页，只声明当前来源窗口，不推测存在其他结果。
- 榜单优先通过结果数量参数一次申请目标深度，不重复请求同一榜单首页充数；本次实测 Google 请求 500、返回 200，响应没有下一页游标。此时保存实际返回范围并标记“未达目标数量”，不宣称完成 500 条。Apple RSS 榜单使用最多 200 条窗口。
- Apple 评论仍受 RSS 分页约束：依据来源的下一页标记继续，不根据短页推断结束；无导航时读取至空页。最多读取来源支持的 10 页，达到来源窗口但未取足目标时标为 `reviews_source_limit`，不宣称历史全量。
- 分页遇到游标循环、连续没有新增数据、解析失败或请求失败，报错并保留上次完整结果，不能把已取得的部分页发布成完整成功。已完成的同批其他目标仍独立保存。日志记录目标数量、实际数量、响应次数和停止原因。Google 响应通过每次调用的独立标识映射，支持乱序返回；详情另外校验应用 ID。单项缺失或格式异常只将该目标标成失败，按原退避机制改用原有单目标协议重试，不保存不完整结果或捏造空数据。HTTP 限流依旧执行共享冷却，不立即拆批轰炸请求。
- 此优化不自动降低目标深度、延长采集周期、删除任务或复用过期数据。请求次数下降来自传输层的合并；原有字段、排名、评论、各目标历史仍独立完整保存。
- 跨页暂停/恢复、周期调整、失败重试使用 MySQL 临时表固定目标集合，并以集合更新及批量日志写入完成同一事务；不将几十万个 ID 拉到 API 内存，不逐任务发出数据库更新。选中任务仍支持至多 100 项的原子操作。
- API 批量操作新增 `action=interval`（携带 `refresh_hours`）及跨页 `action=retry`；跨页立即采集 `refresh` 仍不支持，避免误触全量重采。全池任务通过基础流程控制，不包含在配置目标列表的“全部”操作中。

回归覆盖 105 个同市场 Apple 应用分 3 个 HTTP 请求、21 个 Google 详情/关键词分 2 次请求、完整字段/排名对比、评论独立游标与完整深度、响应乱序/部分缺失、失败目标单独重试、并发领取、暂停后的过期结果丢弃、每日预算跨日重置、图例筛选与跨页周期调整。

2026-11-06 使用真实 Google 接口的小样本验证结果（未写入生产观察数据）：

| 数据 | 原协议所需 HTTP 请求 | 批量请求 | 返回数据 |
|---|---:|---:|---|
| 两个应用详情 | 2 | 1 | 两份详情；已核对原 21 个业务字段 |
| 两个关键词 | 2 | 1 | 各 20 条，沿用原首屏覆盖语义 |
| 两个分类榜单 | 2 | 1 | 各 100 条 |
| 两个应用评论 | 4 | 2 | 各 100 条，独立两页 |

上述两页评论是旧的每页 50 条实现验证记录；2026-11-06 后续实测中，改为单次请求 500 后获得了 500 个不同评论 ID。

“采集深度”是每个目标需要的结果数量，当前关键词最高 200、榜单/评论/推荐最高 500；“20 个目标/批”是 HTTP 合并目标数，不是结果条数。100 仅为表单默认值与先前验证样本量。数据量大于单次接口窗口时，自动续采是内部行为，用户仍只提交一次任务。来源不提供稳定快照或完整历史窗口时，不能承诺获得商店全部历史数据；代码保证不跳过已知游标、不重复计数、不把失败的半成品伪装成完整结果。

Google 多 RPC 是网页公开协议而非稳定官方 API；批次格式变化时按上述单目标重试保留数据覆盖。请求合并比例取决于同市场待采集应用数量，不代表所有类型都能减少相同比例，也不承诺任意规模在一天内全部采集完成。

完整语义及备份、恢复、打包命令见 [离线部署说明](offline-deployment.md)。
## 统一调度与历史任务整合

常驻 console 和 keywords 进程共用数据库中的调度顺序。空闲进程从已启用且到期的详情、关键词、榜单、评论、推荐、权限、图标和全池队列中选择一类，每次领取一个兼容批次，完成后重新参与分配。暂停目标、未到期目标和有效租约不会被再次领取。进程退出后，目标在租约到期后可由其他进程接手。共享限速、冷却和预算作用于实际 HTTP 请求。

计划相同目标按原有唯一身份合并，普通新计划采用较大深度与较短周期，保留暂停状态。带 preserve_existing 的预设计划尊重用户先前编辑。计划记录的“采集结果”按目标实际观察时间显示完成或失败，多个计划可引用同一结果。周期和深度仍可在采集中心直接编辑。

Google 同市场批次内，相同 RPC 内容只发送一次，结果映射回每个目标。权限纳入任务卡片、列表和批量控制，支持同地区最多 20 个应用一次请求。Apple 非批量接口和图标下载按来源协议执行，工作进程仍动态分配。

本地整理命令为 `python scripts/reconcile_collection.py --apply --pool-service-stopped --output <报告路径>`，在采集进程停止期间执行。清理过期租约、补回缺失详情任务，将已停止的全池服务映射为流程暂停。前后核对任务数、启用/暂停数、周期合计和深度合计，保留任务 ID 与历史。已启用全池的环境省略 `--pool-service-stopped`。

种子同步、发现和新市场队列扩展仍由 monitor 流程负责。显式启用全池后，现存队列可由共享调度器领取。第三方授权数据源保留自己的更新流程。

## 系统接入与批次提交

`POST /api/research/collection/enqueue` 沿用采集写权限，可由平台页面、外部系统或定时调用者提交。请求示例：

```json
{"source":"crm","request_id":"2026-11-06-refresh","tasks":[
  {"kind":"keywords","store":"google","country":"us","language":"en","keyword":"loan","depth":100,"refresh_hours":24},
  {"kind":"permissions","store":"google","country":"us","app_id":"com.example.app"}
]}
```

一次接受 1–500 个目标，支持 details、keywords、chart、reviews、featured、icons、permissions。整份提交先校验再保存。同一来源、同一请求编号、同一任务内容会返回同一个回执；编号相同而任务内容不同会拒绝。返回的 id 可用于 `GET /api/research/plans/{id}/collection` 查询每个任务的实际结果。周期目标到期后再次进入可领取状态，各来源共享同一目标身份。已有暂停状态和失败退避继续生效。

消费者在商店、国家、语言和协议兼容范围内尽量取满配置批量。HTTP 限流与网络超时的到期重试仍可组批，结构异常及缺失项保持单目标核验。结果写入和任务确认在同一数据库事务提交，评论、榜单与关键词明细使用批量插入。批次中途写入失败则整批回滚，任务保持未完成并在租约过期后重新领取。

`GET /api/research/collection/revision` 是轻量变更检查。入库提交后递增版本，采集中心每 5 秒检查一次，仅发生变化时刷新数据。用户编辑设置、打开弹窗、选择任务或离开页面时会延后或停止自动刷新。刷新显示的是已提交的结果。

## 采集血缘视图

入口为采集中心的“采集血缘”，或 #collection?view=lineage。参考天枢的分层关系图与上下游聚焦，支持节点搜索、方向筛选、节点详情、拖动画布、缩放适配和对应任务/数据入口。操作工具位于画布内，连接锚点在节点左右边缘正中，流向动画可暂停。

节点数字统计任务：队列为当前目标数量，消费节点为窗口内实际领取次数，来源及结果节点为窗口内目标执行次数。连线数字统计交互：提交目标次数、队列消费次数、真实 HTTP 请求次数、成功入库条数分别使用独立单位。一次多目标 HTTP 只计一次，未记录实际交互的连线仅保留连接关系，不显示数字或占位文字。动画只表示方向。

任务分配与 HTTP 埋点从本功能启用后开始记录。过去的入库量可从目标观察记录读取；未持久化的历史请求量、按需来源返回量不回填。返回量口径为每目标成功入库条数，含重复采样，节点面板显示来源、单位、失败数、时间和对应存储表。图标按保存成功的采集执行计数。全池已排除重点任务重叠。时间窗口为近1小时、24小时或7天，快照缓存最多60秒，画布刷新按钮立即重新读取。
# ASO 一次性任务

队列接收任务不依赖周期。Apple 搜索热度查询、Apple 格式热度响应导入和 ASO 报告导入均先写入持久队列，API 返回 `resource=sources`、任务 `id` 和 `status`，不会在提交请求中访问外部来源或执行入库。

现有统一消费者在空闲时每 5 秒检查队列，有任务即持续消费。`sources` 与详情、关键词排名等队列共同参与动态分配。一次性任务成功后 `due=NULL`，状态为 `done`，不会重新生成周期任务。失败按退避重试，最多自动尝试 3 次；可在采集中心查看原因并重新入队。暂停、租约过期恢复和手动重试均保留任务回执。

同国家、分类和统计时间范围的 Apple 请求默认每批合并最多 2000 个逻辑任务，以其中最大的结果上限请求一次，结果按各任务语言归档。同一批次相同归档只写一次，随后批量更新每个任务结果；数据和完成状态在同一事务提交。来源返回不足或达到上限仍保留原有范围标记，不假定已获取全量数据。上传报告和响应不产生外部 HTTP 请求。

提交入口：

- `POST /api/discovery/keywords/apple-popularity`：热度采集入队。
- `POST /api/discovery/keywords/apple-popularity/import`：上传响应入队。
- `POST /api/discovery/reports/import`：报告入队；原预览接口保持同步校验。
- `POST /api/research/collection/enqueue`：支持混合提交 `aso_popularity`、`aso_import`、`aso_report` 和原有任务类型。来源和请求编号用于幂等校验。
- `GET /api/discovery/keywords/tasks/{id}` 或 `GET /api/research/collection/source-tasks/{id}`：读取状态与完成后的 `result`。回执不包含上传内容或授权凭据。

页面提交后自动跟踪回执并刷新结果；离开页面不会取消任务。采集中心增加对应分类、已完成状态、日志、一次性任务详情与重新入队操作，血缘图区分任务数量、实际 HTTP 请求和文件处理次数。授权配置由 API 和消费者共用服务端环境变量。

## 请求合批与数据复用

- 每个消费者服务默认启用 `collector_concurrency=4` 个逻辑消费者，共享 Google RPC 与 Apple Lookup 合并执行器。请求按国家、语言、会话身份和连接设置隔离，短暂汇集兼容任务并优先填满单次请求。同市场的详情、关键词、榜单、评论、权限可共用一组 Google RPC；重点详情、全池详情及图标补查可共用 Apple Lookup。
- `google_rpc_batch_size=20` 是单次 HTTP 的不同 RPC 上限，`apple_lookup_batch_size=50` 是不同应用 ID 上限；相同调用先去重再分发结果。`collection_batch_size=2000` 是图标及 ASO 任务的逻辑回填上限，可配置为 50–2000，不能等同于向上游提交 2000 个不同 RPC。
- 图标分为地址准备和图片下载两个阶段，每轮只领取下一次实际请求能处理的任务。缺少地址时按市场批量读取完整详情并保存地址；相同图片 URL 的任务共享下载，逐任务保留周期、状态和租约。同一时刻其他消费者已取得的图片可复用；后续刷新周期仍重新请求，不以旧文件伪造新的采集时间。
- 任务等待或返回结果时仍检查暂停和租约；批次响应按请求编号分配，缺项和解析错误只进入相应任务的失败路径。Apple 多 ID 缺项仍保留单独核验，避免误判下架。关键词、评论原有续页逻辑、目标深度和返回顺序保持不变。
- 固定 Git 版本的词频文件按来源 URL 与内容校验值缓存，多个市场、不同提取数量在本地解析。单文件缓存上限 8 MiB，更大的文件保留原始完整解析方式。
- 血缘图增加 Google 联合批次和 Apple 联合详情节点。任务分配数量与实际 HTTP 独立统计，一次混合请求只记一次 HTTP；分页不会重复增加已分配的逻辑任务数。

验证包括乱序响应映射、跨市场隔离、部分失败、取消与租约、刷新周期、批次边界及大批回填。真实 Google 接口已验证详情、关键词、榜单、评论、权限五种调用在一次 HTTP 中分别返回可解析的数据。
