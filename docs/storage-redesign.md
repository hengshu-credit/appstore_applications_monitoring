# OceanBase + SeaweedFS 改造验收

日期：2026-11-09。运行时版本：0.5.0。

## 行为变化

- MySQL 服务由 OceanBase 替代，连接配置使用 OCEANBASE_*；客户端会检查服务端版本并拒绝 MySQL 运行时。
- 图标、图片、直接 CDN 视频、详情正文、原始响应、市场数据归档、报告及导出文件写入私有 SeaweedFS 对象空间；正文/响应使用无损 Zstd，媒体原字节保留。
- SeaweedFS 文件元数据存入 OceanBase，部署不需要第二种关系数据库。
- 排名、榜单明细、每日指标、事件、请求与日志采用列式表，队列/账户/配置采用行式表。
- 限量 SKIP LOCKED 查询改为候选键分页和主键锁定。跨业务提交的互斥使用独立事务连接，入队请求增加来源/编号唯一约束。
- 不再在每次 API 连接时执行建表；Compose 初始化服务负责建立新库和对象桶。没有旧格式回退或自动历史迁移。
- 备份格式 4 包含对象原文校验所需元数据，流式校验大对象；恢复到空库/空前缀，拒绝旧格式和覆盖已有数据。

- 前端：111 项测试通过，语法检查及 Vite 构建通过。
- 独立跨平台客户端/解析测试：59 项通过。
- Python 编译、pip check、生产和开发 Compose 配置校验通过；后端与前端 Docker 镜像构建通过。

## 已修正的 OceanBase 差异

1. LIMIT 在 SKIP LOCKED 前发生，锁住队首时可能提前返回空：按候选主键逐条锁定并跨页查找。
2. 行别名 UPSERT 与时间函数组合出现内部错误：直接使用 VALUES(column)，不添加运行时 SQL 兼容翻译层。
3. FOR SHARE 查询：改用事务内 FOR UPDATE 保持角色读取/更新的一致性。
4. UNION 被裁剪成单分支后输出字段名可能变化：显式投影字段别名。
5. 并发相同入队请求可能出现多回执：独立锁事务与数据库唯一约束共同保证幂等。

## 部署边界

默认是单机 Compose。多机数据节点使用 compose.volume.yaml；主机叠加 compose.storage-network.yaml 发布受控私网端口。增加节点不自动配置副本、重平衡或高可用，不能将同机多容器称为跨机器容灾。

OceanBase 快速启动镜像用于单机开发和验收，正式集群需要按照官方生产部署流程及故障恢复验证实施。内置压缩减少表数据，但固定内存、预分配日志、索引、副本与对象元数据都必须计入实际容量。

完整命令见 README.md、offline-deployment.md。旧 data/mysql 目录不会自动删除。远程 CI 状态以最终提交 SHA 为准，本地通过不代表远程 CI 已通过。

OceanBase 与 SeaweedFS 已启动，前端 5173、API 8765、OceanBase 2881、S3 8333 均可用；API 版本为 0.5.0。实际对象读写和 SHA256 校验通过。新库应用数为 0，初始化管理员待用户完成；本项目旧 MySQL 容器已停止，原数据目录保留，未执行历史导入或删除。

视频归档能力已接入允许的 CDN 直接媒体地址，现有 config.toml 的 archive_videos=false 策略保持不变；需要采集视频时可显式启用。数据库替换与对象存储切换不自动扩大采集范围。
