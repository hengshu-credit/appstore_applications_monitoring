# 衡枢·观星监控研究与实现

研究日期：2026-11-03。目标是可追溯的应用观察与复核工作台，覆盖 App Store / Google Play；所有统计限定商店、国家和请求语言。

## 参考与复用判断


| 来源 | 观察到的能力 / 可借鉴点 | 衡枢·观星的选择 |
|---|---|---|
| 外部报告 | 应用档案、全球市场、排名与评分趋势、版本与素材、开发者、下载收入模块 | 档案与趋势分层，保留当前市场与来源时间；无数据的下载收入明确缺少来源 |
| 关注名单 | 双商店状态卡、每日快照趋势、近期上下架名单、评分分布与国家统计 | 增加一级“上下架观察”；状态卡、采集质量、复核队列和事件入口形成工作闭环 |

| [google-play-scraper](https://github.com/facundoolano/google-play-scraper) | MIT；公开详情、搜索、榜单和评论接口 | 保留已有解析器与错误检测，不为接入另一个 Node 服务重复构建采集层 |

## 指标获取与判定

| 内容 | 数据来源与存储 | 判定 / 限制 |
|---|---|---|
| 上下架 | 详情请求 → requests、listings、events、原始响应 | 复用配置的缺失次数和复查间隔，默认至少3次、相隔24小时；403/429/5xx/解析失败只记错误。未查到限定当前市场 |
| 首次发现 / 首次验证 / 重新出现 | apps.first_seen、first_verified、reappeared | 三种独立时间，首次入库或验证不代表刚上架。初次就不可用也不是已知在架应用的下架事实 |
| 版本 / 素材 | 内容变化快照及字段 diff | 商店发布日期、版本更新时间、系统观察时间分别展示；相同版本也可有元数据变化 |
| 关键词覆盖 | 启用词库逐词搜索，keyword_runs / keyword_ranks | 当前覆盖只计最新尝试成功且未过期的命中词；TOP3/TOP10同口径。不能得出全网覆盖数 |
| 覆盖趋势 | 每个词每日最后尝试，分日聚合 | 展示成功样本数/尝试词数；词库变化会改变分母，不宜直接用其涨跌推断清词。缺失日期不补0 |
| 榜单 | 独立的商店/市场/分类/榜单快照 | 未命中只代表未进入返回范围。派生榜与公开榜分开标记 |
| 清词 / 清榜 | 同目标历史排名、成功状态、范围与详情健康度联合核查 | 仅输出疑似掉词/持续出榜；不能证明 Apple 或 Google 处罚 |
| 评分 / 评论 | 公开评分数、评分及已采集评论 | 累计评分不等于评论条数；“每日新采集评论”按 first_seen 计，不冒充商店当天新增 |
| 下载量 | 开发者授权报表或合法第三方估算 | Apple 任意竞品日下载量不由公开详情接口提供。Google 累计安装下限不可相减推算日下载 |

真实下载量的下一步接入：自有 Apple 应用使用 [App Store Downloads 报表](https://developer.apple.com/documentation/analytics-reports/app-download)，通过 [App Store Connect 报表能力](https://developer.apple.com/help/app-store-connect/measure-app-performance/overview-of-reporting-tools) 获取；区分首次下载、重新下载、更新与恢复。Google 使用开发者私有 GCS 中的 [Play Console 导出报表](https://support.google.com/googleplay/android-developer/answer/6135870?hl=en)，保留原始字段及延迟，不承诺固定到达时刻。竞品估算必须标注供应商、模型版本、地区、日期、估算属性和修订批次。

建议下载事实表唯一键为 `(provider, store, app_id, country, metric, date, device)`，同时保存 `value, unit, is_estimate, source_revision, imported_at, raw_path`。重导入按来源修订替换，按同指标同设备聚合，不与广告安装归因表混算。授权适配器及下载事实表本轮未接入；界面保留明确空态，不能把模拟值当作结果。

## 上下架观察：适合衡枢·观星的方案

入口保持一级菜单平铺。顶部沿用全站商店、国家、语言；页面提供7/30/90/365天区间，不把不同市场相加后称为应用去重总数。

1. 状态卡：已观察在架、待复核、地区不可用、未验证的重点应用。基线中的数百万历史 ID 不计作当前在架。
2. 质量栏：已观察数、48小时内检查数、统计时间及区间采集成功/缺失/错误数。失败不覆盖有效状态；旧状态需要结合新鲜度看。
3. 每日状态快照：`availability_daily` 按市场和 UTC 日保存 stock counts。console worker 每小时原子汇总一次，更新当日最后快照。worker 中断留下日期缺口，页面不补造历史，当前日也不是日终终值。
4. 待复核队列：单次/多次缺失、计入缺失次数、最后检查和请求错误；点击应用查看时间线和证据，再通过采集中心安排复核。
5. 状态事件：首次验证、重新出现、地区不可用分别展示，最多100条，详情保留字段差异和历史。

不采用未经校准的“国家下架风险指数”：观察样本选择偏差、地区访问限制和采集质量都可能改变占比。后续可以做“当前样本地区不可用占比”，同时显示分子、分母、样本选择、更新时间；它也不是监管处罚率。跨商店同名应用应先建立人工确认的产品关联，不凭同名直接合并。无评分样本不当作低评分。

状态机复用既有逻辑：未知 → 可访问；有效缺失 → 待复核；达到次数与间隔 → 地区不可用；重新访问成功 → 在架并记录重新出现。HTTP/TLS/解析异常走独立重试通道。对重点应用可以设置更短的采集周期，但缺失确认间隔仍由后端约束。

后续规模化建议：为每次任务记录预计复查时间、批次与采集源质量；按国家设置熔断，来源大面积失败暂停异常判定；事件证据关联连续尝试和原始响应；到期任务优先于全池长尾。新增日汇总从上线开始积累，不根据今日状态反推过去30天。现有日表统计的是已观察样本，并非固定样本队列，池变化也会改变曲线。

## 库外搜索入库

`POST /api/discovery/search` 接收当前市场和 query。名称走公开搜索，最多30条；ID或官方 HTTPS 链接提取规范身份，再请求固定商店 endpoint。仅允许 apps.apple.com / play.google.com 的对应应用链接，拒绝混商店、任意主机、凭据和非标准端口，服务端不直接请求用户提供的 URL。

预览返回名称、ID、是否已入库、来源和时间。点击入库执行 `POST /api/discovery/import`：重新核验当前市场详情 → `(store,app_id)` 幂等入库 → 复用应用一键采集计划。名称搜索不会自动把所有搜索结果加入重点池。详情核验失败不入库、不宣称下架；已有应用复用进行中的计划。历史快照和原始响应由常规采集 worker 保存，入库成功不等于所有子任务已完成。

## 交互与实施范围

折线图统一替换为时间比例 SVG 图表：整列命中区、即时数据点提示、点击保留、Tab/左右方向键定位、Escape取消选中。提示包含时间、值/排名、采集来源或口径；空值保留断线，SVG内容转义。条形图支持悬停和聚焦提示。窄屏图表在自身容器滚动，颜色复用衡枢·观星主题，不引入外部运行时 CDN。

详情新增应用档案、市场可用性、榜单/关键词历史切换、采样覆盖、累计评分数、评论分布、新采集评论、安装下限趋势和疑似清词/清榜证据。原有市场矩阵、素材快照、版本差异、ASO工作台和采集计划继续使用。

异常提示目前是查询时证据核查，不是持久化处罚结论或新通知通道。要求详情48小时内在架；三个连续尝试同来源/解析版本/覆盖范围（关键词还要求相同请求深度）；基线有排名、后两次成功缺失且返回数仍覆盖旧位置；相邻观察至少1小时；最新采集未过期。至少3词才提示批量掉词。规则阈值是衡枢·观星的保守核查条件，不是商店官方定义。

历史查询当前上限：每类200个启用目标、每目标300次区间内尝试、详情快照300条；超限返回提示。长期词库需要预聚合和分页；此上限不等于真实词库总量。暂未接入授权下载、私有收入、全历史版本与评论、全市场关键词、付费第三方接口。
