# 榜单增长、跨市场关键词与点点报告

研究日期：2026-11-03。此轮在现有 Python/MySQL/独立前端中实现榜单和关键词发现，不迁移 AppGoblin 的整套 PostgreSQL/Svelte 系统。

## 已实现入口

- 榜单中心：保留七类直接/派生榜单；增加历史日期、1/7/14/30天比较、可比较范围的新入榜/出榜、列显示、CSV导出和批量重点监控。
- 增长与新应用：按累计评分数净增长或 Android 公开累计安装数变化排序，支持分类、应用名称、免费/付费、广告/内购、近7/30/90天发布筛选。
- 关键词中心：覆盖与排名、候选词库、应用报告、热搜来源、市场覆盖五个视图。
- 应用详情：新增跨国家/语言的关键词覆盖矩阵和当前市场第三方报告数量。
- 点点报告：xlsx预览、市场检查、应用绑定、按SHA256幂等导入、ASO/ASA分表查询、原字段查看、选词加入候选库、候选词加入周期追踪。
- 开源词库：固定版本的 FrequencyWords 下载导入，支持22种语言/语言变体；也可手动导入多国家同语言词表。仅入候选库，不自动产生海量网络任务。

## 榜单和增长口径

原有 `installs` 字段继续表示Google安装档位下限。新增 `installs_reported` 来自现有解析器的 `realInstalls`，不改写旧指标含义。`has_ads`、`has_iap` 同时保存；来源未返回则为空。

`app_metrics_daily` 在每次有效详情采集时写入，即使详情内容未改变也保留每日观察。每个商店、应用、请求国家、语言、UTC日期保留当天最后一次成功观察及原始响应位置；迟到观察不能覆盖较新的日记录。失败不会伪造日指标。

- 安装数是Google公开全球累计指标的观察差值，不是请求国家的下载量，不把多个国家的重复观察相加。
- 评分数变化是同口径净变化，不是新增评论条数，更不是下载估算。
- 起止边界各取不晚于边界、最多向前36小时的最后有效观察，实际跨度不足指定窗口减12小时则不给增量。响应保留实际起止时间和跨度。
- 环比为本窗口增量与前一个同长度窗口增量的比较；前窗口为零、缺失或来源版本不一致时为空。
- 负差值标为累计数回调，不伪造成负下载或正常增长。
- Apple公开详情没有累计安装数。选择安装增长时明确显示来源不可用。
- 新应用按商店发布日期筛选。首次发现、首次验证不等于首次发布。

历史榜单按指定时点选择成功快照，不用未来快照。比较只用于同来源、解析版本和覆盖类型。新入榜/出榜只判断两次实际返回深度可比较的范围；不能把超出采集范围当作商店下架。派生新畅销榜历史查询也只读取当时已保存的发布日期。

## 多国家词库怎么建设

身份维度是 `(store, country, language, keyword)`。同一语言可以共享候选词，但各国必须分别请求并保存排名；不同语言不会通过翻译直接继承排名、热度或覆盖。CLDR与现有商店语言配置用于建议默认请求语言，不证明所有国家已实测成功。

建议顺序：应用合法导出报告/品牌词 → 当前地区应用名与人工行业词 → 开源语言词库补充 → 精选关键词持续采集 → 从搜索结果反查应用覆盖。

当前应用覆盖榜计入：启用目标、最新成功、无未解决失败、未过期、实际请求深度与当前配置一致的搜索结果。显示当前词库跟踪数和有效数，以及Top3/10/50/100覆盖。每个应用页可查看多市场覆盖。未跟踪的词属于未知；观星词库规模不同于点点，覆盖数不能直接等同。

覆盖榜最多返回200应用，市场词表500词，单应用查询1000词；候选词与报告列表按100行分页。增长结果由MySQL对全部符合条件的日观察排序后返回前200条，不在浏览器对百万数据排序。

## 热搜榜的实现与剩余数据条件

用户指定的 [热搜榜](https://app.diandian.com/rank/hot-75) 和 [覆盖榜](https://app.diandian.com/rank/cover-1-1-75-0-0-0-0) 是动态页面。普通网页读取超时或只有空壳；浏览器连接也未完成读取，之后工具因无法可靠确认页面地址停止。本轮未取得、未宣称验证其登录后热搜数据或隐藏API。

已实现来源快照导入/查询：按商店、国家、语言、来源、日期保存外部热搜或搜索热度，保留排名和分数单位；多个来源不合并成伪统一指数。无来源时显示未接入，不用语料词频、搜索结果数或单应用报告冒充全市场热搜。

后续可接合法平台导出/API或商店明确公开且实测有效的热门查询来源。Google Trends是Web搜索兴趣，搜索联想是候选补全，两者都不直接等于App Store热搜。
