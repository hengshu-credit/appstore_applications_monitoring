## 使用入口

- 关键词中心 → 候选词库：总词库，可筛选、查看来源、选择词条追踪。
- 关键词中心 → ASO词库：独立查看自然搜索词，按当前商店、国家、追踪语言分页与筛选，查看历史报告最佳排名、来源应用数和报告日期。
- ASO工作台：加载应用后，底部“ASO报告词库”展示该应用、该市场的自然搜索词；筛选后可将本页加入核查词库，保留已有人工词并去重，最多500词。此操作不改动文案字段或保存草稿。

## 文件与口径

`keyword-library.jsonl` 每行一个 `(store, country, language, keyword)` 身份，`sources` 保存全部来源、许可、署名、来源期与可用语料词频。`aso-library.jsonl` 使用同一身份维度，`sources` 保存应用 ID、报告哈希、文件名、日期、原始行号、报告排名/搜索指数/流行度及原字段。`manifest.json` 保存版本、来源文件清单、重复文件、分市场计数、完整性检查和 SHA256；只有构建成功才写出。

关键词使用现有 NFKC 和空白规范化规则，保留大小写。国家不互相合并，同一语言不复制其他国家的排名。`language` 是导入时指定的追踪配置，报告未确认搜索请求语言；哈萨克斯坦报告中的俄语、哈语等原词均保留，不自动翻译或推断语种。

ASO 库不包含 ASA / 谷歌付费词表中独有的词。保留报告中的零值与缺失值；不把搜索指数、流行度、报告排名转换为官方搜索量、本站实采排名或实时热搜。UI 的“最佳报告排名”是所选历史报告中的最小正排名，与“最近报告日期”不是同一行观察。

## 后续重建

绑定文件每项为 `prefix`（文件名前缀）、`store`、`app_id`、`country`、`language`。新增应用须填写已核实的应用绑定，不能只根据名称猜测 ID。脚本在写入前核对所有文件，拒绝缺失/冲突绑定和市场不符。报告按哈希幂等入库，候选词保留原来源，同一数据重复运行不会增加词条或追踪任务。

```powershell
.\.venv\Scripts\python.exe scripts/build_initial_keyword_libraries.py C:\Users\Administrator\Downloads --bindings data/report-bindings.json --output data/keyword_libraries/v2
```

输出目录必须不存在，以保留旧版本。两个词库使用同一个 MySQL 一致性快照导出，逐行回读检查规范化身份、重复项、来源记录计数，并与数据库核对。未来版本会包含构建时全部已有候选词和已导入 ASO 报告，不只本次目录中的增量。
